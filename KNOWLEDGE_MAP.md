Real-world systems revisit earlier stages and operate across several stages simultaneously.

## 2. Connections between the six parts

| Transition | Bridge question |
|---|---|
| Reality → Information | How do we represent what we observe so it can be stored and processed? |
| Information → Systems | How do we organise machines and software to process information reliably at scale? |
| Systems → Intelligence | How do we derive useful knowledge from collected and processed data? |
| Intelligence → Decisions | How do we decide what to do with predictions, inferences and generated content? |
| Decisions → Future | How do we evaluate, govern and improve systems that influence the world? |

## 4. Cross-cutting concepts

| Concept | Where it connects | Why it matters |
|---|---|---|
| Representation and abstraction | Parts I–IV | Every model, schema, feature and embedding represents selected aspects of reality. |
| Uncertainty | Parts I, IV and V | Measurement, inference, prediction and decisions all involve uncertainty. |
| Data quality and provenance | Parts I, III and IV | Evidence and model outputs depend on the quality and origin of data. |
| Scale and complexity | Parts II–V | Computation, storage, distributed processing and AI face resource constraints. |
| Reliability and failure | Parts II–V | Correctness must survive software changes, concurrency, networks and operational conditions. |
| Security and privacy | Parts II–V | Trust and acceptable use are properties of the whole system. |
| Evaluation | Parts I, IV–VI | Models, predictions, systems and technology claims need evidence. |
| Feedback and adaptation | Parts V–VI | Outcomes influence future decisions, models and systems. |
| Human and organisational context | Parts I, V–VI | Technology is shaped by people, incentives and institutions. |

## 5. Supporting subjects: enough depth to connect

These subjects do not automatically require dedicated deep-dive chapters.

Teach enough to make the dependent concepts understandable.

| Supporting subject | Minimum useful understanding | Enables |
|---|---|---|
| Networking | Packets, protocols, latency, partial failure and APIs | Distributed systems, cloud and integration |
| Operating systems | Processes, threads, memory and concurrency | Computation and system behaviour |
| Software engineering | Modularity, interfaces, testing, version control and deployment | Maintainable data and AI systems |
| Linear algebra | Vectors, matrices, transformations and similarity | Machine learning and neural networks |
| Statistics | Samples, distributions, inference, uncertainty and experiments | Analytics, ML evaluation and decisions |
| Security | Identity, authentication, authorisation, least privilege and threats | Safe data sharing and intelligent action |
| Economics | Costs, constraints, incentives and opportunity cost | Architecture and decision quality |
| Human cognition | Bias, attention, interpretation and judgement | Dashboards and human-AI interaction |

## 6. Recurring real-world example

Use a banking transaction and credit-decision system as one longitudinal example.

| Learning stage | Example |
|---|---|
| Reality | Transactions, customers, events and risk |
| Representation | Records, identifiers, measures and categories |
| Computation | Rules, algorithms and protocols |
| Systems | Databases, event streams and analytical platforms |
| Evidence | Statistical analysis, fraud patterns and model evaluation |
| Intelligence | Predictions, classification and generative interfaces |
| Decisions | Approve, decline, investigate or request more information |
| Outcomes | Customer impact, losses, fairness, feedback and governance |

Use contrasting examples from healthcare, manufacturing, transportation, retail, science and everyday life to demonstrate that the principles transfer beyond one industry.

## 7. Unfamiliar-technology transfer test

At the end of each major part, ask readers to investigate an unfamiliar technology.

1. What problem does it address?
2. What capability does it introduce?
3. What is the underlying mechanism?
4. What assumptions does it make?
5. What trade-offs and failure modes does it introduce?
6. What evidence would help evaluate its claims?
7. What consequences follow from using it?

Understanding is demonstrated by applying a concept to a new situation, not merely repeating its definition.

## 8. Maintaining this map

Update this document when:
- A new dependency is identified.
- A concept is moved between chapters.
- Two capsules overlap significantly.
- A missing foundational concept is discovered.
- A new technology exposes a gap in the existing mental models.

Do not add concepts simply to increase syllabus size.
